# IC Preflight 심사위원 재현 카드

## 한 문장

화면의 검증 시나리오를 `자동 확인`으로 둔 채 `검토 요청 한 문장`에 다음 문장을 입력한다. 같은 결과를 고정 재현하려면 `기간 불일치 · 동일 입력 비교` 시나리오를 직접 선택해도 된다. 입력 문장은 Agent 상태와 감사 로그에 저장된다.

> 대상 기업의 FY2025와 비교기업의 9M FY2026 실적을 비교해줘

Agent는 `FY2025`와 `9M FY2026`의 기간 신호를 읽고 `period_mismatch` 경로를 선택한다. 기대 결과는 `VERIFY fail → REPLAN → 원문 재조회 → IC Preflight HOLD`다. 실행 후 감사 로그의 `audit_contract.planning_history`에서 초기 계획과 재계획의 선택 Tool·중단 조건도 확인할 수 있다.

## 기대 결과

| 단계 | 기대 동작 |
|---|---|
| 자료 조회 | target과 Peer의 원문·기준기간을 Evidence Ledger에 연결 |
| 기준 검증 | FY2025와 9M FY2026의 기간 불일치를 `VERIFY fail`로 기록 |
| 재계획 | 승인된 원문 재조회 Tool을 호출하고 기간 보정 근거를 확인 |
| 최종 판정 | 보정 근거가 없으면 valuation을 실행하지 않고 `HOLD` |
| 사람의 역할 | 원문·가정 확인 후 재실행 또는 심의 중단 결정 |

## 화면에서 확인할 것

1. 첫 화면의 `투자심의팩`에서 `보류 · 담당자 승인 필요`를 확인한다.
2. `근거 목록과 상세 실행 기록 보기`를 펼친다.
3. `PLAN → VERIFY → REPLAN → PLAN → TOOL → CRITIC` 순서, 선택 Tool, 보류 사유를 확인한다.
4. 동일 입력 비교 카드에서 기록된 일반 답변 비교군의 `REVIEW`와 IC Preflight의 `HOLD`를 확인한다.

정상 케이스에서는 `Company A의 FY2025와 Peer 3개를 비교해줘`에 해당하는 `정상 케이스`를 실행한다. 필수 근거가 있는 경우에는 `진행` 상태와 결정론적 valuation·민감도가 생성되고, 근거가 빠진 경우에는 `추가자료` 상태가 생성되며 계산은 실행되지 않는다.

고정 예시 외의 입력도 확인하려면 왼쪽 `분석 자료 묶음 · 선택`에서 `data/case_packet_template.json` 또는 승인된 동일 형식의 로컬 JSON을 선택한다. 화면에는 기업명·Peer 수가 표시되고, 서버는 `ic-preflight-case.v1` 계약을 통과한 packet만 실행한다.

통화 안전 게이트도 고정 재현할 수 있다. `통화 불일치 · 환율 근거 확인`을 선택하고 `통화가 다르니 승인된 환율 기준일과 출처를 확인해줘`를 입력하면 Revenue의 `USD/EUR` 혼재를 감지한다. 승인된 환율 snapshot이 없으므로 `currency_alignment_unresolved -> HOLD`가 되고 valuation은 실행되지 않는다.

## 재현 범위와 한계

- 일반 답변 비교군은 모델 없는 baseline이며, 모든 LLM의 일반 성능을 의미하지 않는다.
- 오류 주입 케이스는 KIC 내부 사고 사례가 아니라 안전 게이트의 동작을 확인하는 합성 케이스다.
- 투자 승인·거래·한도 변경은 자동화하지 않으며, 최종 판단은 담당자가 수행한다.
