# 경쟁작 대비 레드팀 검증 v0.2

기준일: 2026-11-07
목적: 다른 팀도 LLM으로 기획서와 데모를 만들 것이라는 전제에서, 심사위원이 우리 Agent를 단순 RAG·아키텍처 쇼케이스와 구분하도록 만드는 실행 전략을 고정한다.

## 심사위원이 먼저 의심할 경쟁작 유형

| 경쟁작 유형 | 심사위원의 의심 | 우리의 반증 자료 |
|---|---|---|
| 내부문서 RAG 챗봇 | 검색은 되지만 투자 결론을 검증하는가 | 동일 입력 H02에서 일반 답변은 REVIEW, IC Preflight typed gate는 HOLD |
| Planner·Retriever·Critic 그림만 있는 멀티 에이전트 | 실제 Tool 호출과 재계획이 실행되는가 | UI의 Planner 제안, typed allowlist, Tool 결과, REPLAN trace, raw JSON |
| 거시·대체·주식·리스크를 모두 다룬다는 플랫폼 | 본선 기간 내 끝까지 동작하는가 | 1기업·Peer 3개·멀티플·공개자료로 범위를 고정하고 10페이지 안에 실행 증거 제시 |
| 오류 주입만으로 100%를 주장하는 시스템 | 처음 보는 오류와 정상 케이스도 처리하는가 | 신규 오류·표현 변형 stress20, 동일 조건 2회, false-hold 별도 공개 |
| 높은 정확도만 강조하는 모델 | 틀렸을 때 멈추고 사람이 복구할 수 있는가 | unresolved → HOLD, 근거 링크, 승인 지점, LLM 장애 deterministic fallback |

## 경쟁작보다 먼저 보여줄 90초 증거 순서

1. 동일 입력 H02: 대상 기업 FY2025와 비교기업 9M FY2026의 기간 불일치
2. 일반 답변의 `REVIEW`와 IC Preflight typed gate의 `HOLD`를 나란히 공개
3. `VERIFY fail → REPLAN → 원문 재조회 → 재계산 또는 HOLD` trace를 화면에서 재생
4. Evidence Ledger에서 source·period·metric definition을 클릭
5. 정상 Mastercard snapshot은 P/S median 3.60과 IC 초안을 만들고, 충돌 케이스는 메모를 중단
6. 모델 호출 실패를 주입해도 결정론적 계산·검증·보류 판정으로 끝까지 실행

## 우리가 주장할 수 있는 것과 주장하면 안 되는 것

### 주장 가능

- LLM은 계획·Tool 제안·Reflection을 담당하고, 숫자 계산·출처 게이트·최종 HOLD는 결정론적 모듈이 담당한다.
- 모델 없이 실행한 stress20 holdout에서 동일 조건 두 실행의 decision이 일치했다. 이는 typed safety gate와 고정 케이스의 재현성 증거이며, 일반 LLM 성능 주장이 아니다.
- 공개자료 snapshot으로 실제 source link·Peer 제외 사유·P/S 산출·IC 초안을 재현할 수 있다.
- `validate_effect_measurement.py`가 사람 stopwatch 없이 시간절감률을 만들지 않도록 막는다.

### 금지

- typed safety gate 100%를 모든 LLM·RAG의 일반화 성능처럼 표현하지 않는다.
- 합성 오류 케이스를 KIC 내부 사고 사례라고 표현하지 않는다.
- 내부 소요시간·오류율·SOP를 확인한 것처럼 쓰지 않는다.
- 모델이 투자 승인이나 거래 결정을 대신한다고 쓰지 않는다.

## 발표 질문에 대한 한 문장 답변

| 질문 | 답변 |
|---|---|
| 왜 RAG가 아닌가? | 문서를 찾는 데서 끝나지 않고 기준일·정의·단위·Peer 적합성을 typed state로 판정하며, unresolved이면 답변 대신 HOLD 또는 추가자료를 반환하기 때문이다. |
| 전부 HOLD하면 안전하지 않은가? | 정상 케이스는 REVIEW로 보내고 false-hold rate를 별도로 측정한다. 목표는 보류율이 아니라 선택적 보류다. |
| 같은 LLM이 검증하는가? | 아니다. LLM은 제안만 하고 Decimal Calculator와 독립 typed Verifier가 최종 게이트다. |
| 오류를 주입했으니 잡는 것이 당연하지 않은가? | 그래서 신규 오류·표현 변형 stress20과 2회 재현 로그를 별도로 공개하고, hand-authored control의 한계를 인정한다. |
| 실무에서 얼마나 줄어드는가? | 아직 주장하지 않는다. 본선에서 동일 packet의 수작업·Agent 시간을 stopwatch로 측정하고 재작업·출처 누락·계산 불일치를 함께 기록한다. |

## 예선 이후 확장 원칙

기능을 넓히기 전에 동일한 증거 구조를 3~5개 기업과 신규 오류 표현에 적용한다. 재사용할 것은 Planner·Evidence Ledger·Verifier·승인·감사 로그이고, 교체할 것은 자산군별 Retriever·지표 정의 사전·권한 정책·출력 템플릿이다.

현재 공개 기본값은 특정 국가·특정 로컬 모델이 아니라 `모델 없음 + 결정론적 안전 게이트`다. 승인 LLM을 연결할 때도 기관 승인 private gateway와 allowlist를 통과한 경우에만 계획·설명 제안에 사용한다.
