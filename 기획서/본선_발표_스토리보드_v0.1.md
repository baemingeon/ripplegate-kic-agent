## 발표 원칙

- 첫 30초에 “틀린 자료가 심의팩으로 넘어가는 위험”을 보여주고 기능 목록으로 시작하지 않는다.
- 정상 결과보다 `충돌 → 재계획 → 그래도 미해결 → HOLD`를 핵심 장면으로 삼는다.
- LLM의 역할과 결정론적 안전 게이트를 화면과 언어 모두에서 분리한다.
- 모든 수치는 실행 로그·원문·계산식으로 클릭/재현할 수 있게 한다.
- 시간 절감·내부 SOP·일반 LLM 성능은 실측 전까지 주장하지 않는다.

## 실제 데모 큐

1. 정상: `실제 공개자료 snapshot · Mastercard` + `모델 없이 안전 게이트 실행` 선택
2. 상세 실행 기록: 자료 조회·기준 확인·재계산·보류 흐름을 5초 안에 보여줌
3. Ledger: SEC Company Facts 링크를 클릭하고 metric·period·verification status를 설명
4. 계산: P/S median 3.60과 implied equity를 보여주되 “담당자 승인 전 초안”이라고 말함
5. 보류: `수치 충돌 후 보류` 실행 → VERIFY fail → REPLAN hold → IC memo HOLD
6. 장애: 승인 LLM이 없어도 모델 없는 안전 게이트로 전환 → 동일한 계산·검증 결과 확인

## 발표자 대사에서 금지할 표현

- “100% 정확합니다” → “관측 신호 기반 observable policy 통제군에서 100%였고, live LLM 일반화 성능은 주장하지 않습니다.”
- “KIC 내부 업무를 자동화했습니다” → “KIC 공개 프로세스에 연결한 검증 업무 가설이며 내부 SOP는 확인 전입니다.”
- “시간을 80% 줄입니다” → “본선에서 동일 packet stopwatch와 재작업 log로 측정합니다.”
- “RAG보다 우수합니다” → “이번 비교군에서 특정 오류 유형을 더 잘 보류했으며, 완전한 RAG 제품 비교는 아닙니다.”

## 10분 Q&A 우선순위

### Q1. 전부 HOLD하면 안전한 것 아닌가?

정상 케이스를 포함해 false-hold rate를 분리 측정한다. 목표는 보류율 최대화가 아니라 중대 오류만 보류하는 선택성이다.

### Q2. 같은 LLM이 추출하고 검증하면 독립 검증인가?

아니다. LLM은 Planner·Reflection만 제안하고 Decimal Calculator·typed Verifier·human gate가 최종 판단을 맡는다.

### Q3. 오류를 주입했으니 잡는 것이 당연하지 않은가?

base와 분리한 표현 변경·신규 오류 stress20을 동일 조건 2회 실행해 결과와 raw response를 보관했다. 그래도 일반화 성능으로 포장하지 않는다.

### Q4. 처음 보는 오류는 어떻게 처리하나?

정의·기간·통화·단위·주식수 기준·출처 중 하나라도 typed state가 unresolved이면 HOLD 또는 human review로 보낸다. 새 오류 유형은 규칙 library에 추가한다.

### Q5. 실제로 몇 분 줄어드나?

아직 주장하지 않는다. 동일 packet의 수작업·Agent 초안 시간을 반복 측정하고 재작업·누락·계산불일치를 함께 비교한다.

### Q6. 내부 자료를 외부 API에 보내나?

MVP는 공개자료만 사용한다. 내부 도입은 private endpoint 또는 승인된 사내 모델, 문서 권한, PII, 보존·삭제정책을 통과한 뒤에만 연결한다.

### Q7. 왜 기업 1개·Peer 3개인가?

발표 안정성을 위해 핵심 gate를 검증하는 최소 범위로 고정했다. gate 통과 후 3~5개 기업과 자산군별 Adapter로 확장한다.

### Q8. Planner가 잘못된 Tool을 부르면?

free-form 이름을 그대로 실행하지 않고 typed allowlist로 canonical name만 통과시킨다. 미등록 이름은 실행되지 않고 trace에 남는다.

## 발표 전 합격 기준

- 90초 안에 정상 실행이 끝나거나 녹화 fallback으로 전환된다.
- 60초 안에 충돌→재계획→보류 Trace가 보인다.
- Ledger 원문 링크 1개와 계산식 1개를 실제로 열 수 있다.
- 모델 장애를 유도해도 결과가 임의의 숫자나 승인으로 변하지 않는다.
- 발표 PDF·GitHub README·데모 URL·원본 log의 숫자와 버전이 일치한다.
