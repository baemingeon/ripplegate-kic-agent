# KIC 업무검증 인터뷰 스크립트 v0.1

목적: KIC 내부 수치나 SOP를 추정하지 않고, 투자 사전검토에서 근거·기간·정의·Peer 검증이 실제로 어디에서 병목이 되는지 확인한다.

## 대상

- 글로벌 주식·기업분석 또는 투자전략·리스크관리 업무를 실제로 수행하는 담당자
- 가능하면 분석 작성자 1명과 검토·승인자 1명을 분리
- 인터뷰 기록에는 실명·민감 정보·비공개 자료를 남기지 않고 역할만 기록

## 질문

1. 기업 또는 Peer valuation packet을 만들 때 가장 자주 다시 확인하는 항목은 무엇인가?
2. 기준일·보고기간·통화·단위·Adjusted 지표 정의가 어긋난 사례를 어떤 단계에서 발견하는가?
3. 근거가 충돌하거나 부족할 때 현재는 누구에게 어떤 형식으로 확인을 요청하는가?
4. 초안 작성에서 수작업 전환이 가장 많이 발생하는 지점은 무엇인가?
5. Agent가 자동으로 해도 되는 행동과 반드시 담당자가 승인해야 하는 행동은 무엇인가?
6. 결과 화면에서 출처·계산식·보류 사유 중 무엇을 가장 먼저 확인하고 싶은가?
7. 공개자료로 시작한 MVP가 내부 도입될 때 가장 큰 보안·권한·라이선스 제약은 무엇인가?

## 기록 양식

| 항목 | 기록 |
|---|---|
| 역할/업무 유형 | 확인 전에는 비워 둠 |
| 관찰된 task | 기업·기준일·Peer·valuation method |
| 현재 입력 packet | 문서·표·API 결과의 유형만 기록 |
| 수작업 전환 지점 | 확인 전에는 주장하지 않음 |
| 승인 경계 | 확인 전에는 가정으로 표시 |
| 사용성 우선순위 | Ledger·Trace·보류 사유·메모 중 선택 |
| 보안/데이터 조건 | 내부자료 반출·보존·접근권한 확인 |
| 동의 범위 | 익명 요약 사용 여부 |

## 측정 후 기획서에 반영하는 규칙

- 한 명의 의견은 “인터뷰 1건”으로만 기록하고 조직 전체의 사실로 일반화하지 않는다.
- 시간·오류율·재작업 수치는 측정 표본·환경·task 정의를 함께 기록한다.
- 비공개 문서의 수치·스크린샷·이름은 기획서·GitHub·공개 demo에 옮기지 않는다.
- 인터뷰가 없으면 현재 기획서의 “측정 전 가정”을 유지한다.
