# 구현 전제: 모델·보안·PC·가독성 v0.1

작성 기준일: 2026-11-07

이 문서는 IC Preflight를 실제로 만들고 시연할 때 지켜야 할 네 가지 전제—KIC 프로세스와의 관계, 모델 보안, 실행 PC, 화면 가독성—를 고정한다.

## 1. KIC 프로세스와의 관계

IC Preflight는 KIC의 공개 투자 프로세스보다 우수한 별도 투자 프로세스가 아니다. 투자 목표·분석·자산배분·운용계획·실행·모니터링과 위원회 판단을 대체하지 않는다.

제품의 업무 위치는 다음 한 줄이다.

> 투자심의 전에 자료·수치·리스크의 기준을 맞추고, 문제가 남으면 진행·추가자료·보류로 담당자에게 넘기는 사전 점검층

따라서 승부처는 ‘투자 결론을 대신 내리는가’가 아니라, 기준이 다른 숫자가 심의자료에 들어가기 전에 발견되고 그 이유와 다음 행동이 남는가이다.

## 2. 모델 보안 원칙

| 구분 | 기본 공개 MVP | 기관 적용 전환안 |
|---|---|---|
| 모델 | 사용하지 않음 | 기관 승인 모델만 allowlist 등록 |
| 연결 | 로컬 결정론적 Controller·Calculator·Verifier | 승인된 private/OpenAI-compatible gateway |
| LLM 역할 | 없음 | 계획·질의·설명 제안만 수행 |
| 숫자·출처·보류 | 코드 모듈이 결정 | 코드 모듈과 담당자가 결정 |
| 장애 시 | 동일 경로로 계속 실행 | LLM 제안만 버리고 안전 경로로 fallback |
| 내부 자료 | 공개 MVP에 넣지 않음 | 반출·권한·보존 정책 통과 자료만 연결 |

특정 국가의 모델이나 특정 오픈소스 모델을 제품의 전제조건으로 두지 않는다. 따라서 공개 제출물에는 중국산 모델 또는 로컬 14B 모델의 설치·운영을 요구하지 않는다. 모델을 붙일 때는 국가명이 아니라 기관의 보안승인, endpoint 위치, 데이터 반출정책, model allowlist를 통과했는지를 기준으로 한다.

## 3. 현재 PC에서의 실행 범위

현재 개발 PC는 i5-12400F·16GB RAM·RTX 3050 4GB다. 이 사양은 모델 없는 공개자료 snapshot, typed workflow, Decimal 계산, HTML UI와 감사 로그를 실행하는 데 사용한다.

| 실행 경로 | 현재 PC | 판단 |
|---|---|---|
| 공개 snapshot + 규칙 기반 Agent | 가능 | 예선·본선 기본 시연 경로 |
| SEC/IR 문서 수집·정규화 | 가능 | 데이터 양을 MVP 범위로 제한 |
| 로컬 대형 LLM 상시 실행 | 비권장 | VRAM·속도·보안·재현성 리스크 |
| 승인 private gateway 호출 | 가능 | 기관 정책과 네트워크 확인 필요 |

모델이 없어도 핵심 시연이 끝까지 동작해야 한다. 그래야 GPU 부족, API timeout, allowlist 실패가 투자심의팩 생성 자체를 끊지 않는다.

## 4. 화면·문서 가독성 기준

### 기획서

- 본문은 18pt 이상, 표는 14.5pt 이상을 기본값으로 한다.
- 빈 공간을 채우기 위해 글자를 줄이지 않는다.
- 한 슬라이드에는 한 메시지만 둔다.
- 기술명은 Agent 구성 슬라이드와 상세 trace에만 둔다.
- 심사위원이 먼저 읽을 순서는 문제 → 한 문장 입력 → 결과 → 근거 → 다음 행동이다.

### MVP 화면

- 첫 화면은 입력 → 확인 → 판단 → 다음 행동만 보여준다.
- 입력 문장은 한 줄 input이 아니라 여러 줄 textarea로 전체가 보이게 한다.
- 기본 실행 모드는 모델 없이 안전 확인이다.
- 결과 상단에는 진행·추가자료·보류와 담당자 승인 필요 여부를 먼저 보여준다.
- Planner·Tool·Verifier·REPLAN은 상세 실행 과정에서만 보여준다.
- 근거 표는 좁은 2단 분할이 아니라 전체 폭으로 읽을 수 있게 한다.

## 5. 이름에 대한 현재 판단

IC Preflight를 현재 코드와 제출물의 제품명으로 확정한다. 영어 용어를 처음 보는 심사위원도 이해할 수 있도록 모든 표지·화면·문서에 ‘투자심의 전 사전 점검’이라는 설명을 함께 둔다.

| 후보 | 한눈에 전달되는 뜻 | 판단 |
|---|---|---|
| IC Preflight | 심의 전에 하는 사전 점검 | 현재 채택 |
| 투심체크 | 투자심의 전 확인 | 한국어 이해성 후보 |

내부 호환 환경변수와 과거 파일명에 남은 IC_PROOF 표기는 하위 호환용으로만 유지한다. 심사위원이 보는 UI·기획서·README·health endpoint·패키지명은 IC Preflight로 통일한다.

## 6. 구현 완료 판정

- 모델 없이 현재 PC에서 심사위원 재현 문장이 실행된다.
- LLM이 실패해도 안전 경로와 감사 로그가 생성된다.
- 내부 자료가 공개 endpoint로 전송되지 않는 경계가 코드와 설명에 있다.
- 화면과 슬라이드에서 핵심 글자가 읽히며, 기술 용어는 상세 영역에 격리된다.
- 이름·태그라인·실행 화면·기획서가 같은 제품을 설명한다.
