## 이번 버전의 실질 개선

1. 기획서의 메타 문구를 줄이고 서비스 설명을 사례 중심 문장으로 정리했다.
2. 문서에만 있던 핵심 장면을 MVP의 `period_mismatch` 시나리오로 구현했다.
3. UI에 일반 답변 `REVIEW`와 IC Preflight `HOLD` 비교 카드, 투자심의팩을 추가했다.
4. 공개자료·합성 benchmark, 기간 불일치 실행 캡처와 fresh-extract 검증을 release에 연결했다.
5. LLM이 없어도 `typed_policy_v1` Controller가 허용된 Tool을 선택·실행하고, 첫 화면은 심의팩 중심으로 단순화했다.
6. 모델·보안·PC·가독성 원칙을 정본에 명시하고, 특정 국가의 모델을 공개 기본값에서 제외했다.
7. paired 측정표와 준비도 검증기를 추가해 실제 stopwatch 전에는 시간절감률이 나오지 않게 했다.
8. 고정 데모 외에 `ic-preflight-case.v1` 로컬 JSON packet을 받아 같은 안전 게이트로 검증하고, 담당자용 Markdown 심의팩을 저장하도록 했다.
9. 통화가 섞인 동일 지표는 환율 기준일·승인 출처 없이는 환산하지 않고 `currency_alignment_unresolved -> HOLD`로 차단하는 화면·로그·테스트를 추가했다.

## 100점에 가까워지는 다음 게이트

- 팀명·팀장·팀원·연락처 입력 후 PPTX/PDF/ZIP 버전 일치 확인
- 실제 사용자 또는 업무 packet 2건 이상으로 문제 가설 확인
- 동일 packet 5건 이상의 수작업/Agent 시간·재작업·출처 누락·계산 불일치 측정
- 신규 기업 3~5개와 표현이 다른 오류 20건 이상을 별도 holdout으로 실행
- 공개 URL에서 `/health`, UI, `/api/run`, 감사 로그 다운로드까지 fresh 환경 검증
- Demo URL·GitHub 링크가 없는 상태를 숨기지 않고 `READY_AFTER_USER_INPUT`으로 표시한 뒤, 링크가 생기면 동일 validator로 `READY` 확인
- 발표 PDF·GitHub README·demo URL·녹화 fallback의 숫자·버전·한계 문구 대조

현재 상태는 `READY_AFTER_USER_INPUT`이다. 이는 코드 실패가 아니라 팀 정보·외부 링크·실제 paired 측정이 아직 없는 상태다. 사람 stopwatch와 Agent end-to-end 기록이 P01~P05에 모두 입력되기 전에는 업무효과를 주장하지 않는다.
