# IC Preflight 본선 효과 측정 프로토콜 v0.3

목적: 실제 업무효과를 주장하기 전에 동일 입력 packet의 수작업과 Agent 결과를 같은 기준으로 비교한다.

## 실험 설계

- 대상: 동일한 기업·기준일·Peer 범위·질문으로 만든 최소 5개 packet(P01~P05)
- 조건 A: 분석가가 평소 방식으로 초안 작성
- 조건 B: Agent가 Planner·Tool·Verifier·IC memo까지 실행
- 순서 효과를 줄이기 위해 packet 순서와 조건 순서를 교차 배치
- 공개자료로 시작하고 담당자·내부 SOP·실제 투자판단은 기록하지 않는다
- 같은 `packet_id` 안에서 조건 A/B의 시작·종료 범위가 같아야 한다. Agent 서버 실행시간만 기록한 값은 조건 B의 효과측정 값으로 사용하지 않는다.

## 기록 항목

| 항목 | 정의 | 단위 |
|---|---|---|
| 초안 시간 | 입력 packet 수령부터 검토 가능한 초안까지 | 분 |
| 재작업 횟수 | 출처·기간·정의·계산을 다시 고친 횟수 | 회 |
| 출처 누락 | 주장 또는 수치에 연결되지 않은 근거 수 | 건 |
| 계산 불일치 | 독립 재계산과 결과가 다른 수 | 건 |
| 중대 오류 탐지 | gold 오류를 HOLD 또는 human review로 보낸 비율 | % |
| false-hold | 정상 packet을 불필요하게 HOLD한 비율 | % |
| 승인 전환 | 담당자가 초안을 승인·수정·보류로 결정한 비율 | % |

## 측정 전 잠금 규칙

- 수작업 기록은 stopwatch와 review log의 참조가 함께 있을 때만 유효하다.
- Agent 기록은 `measurement_type=human_observed_agent`이고 `timing_scope=end_to_end_workflow`일 때만 수작업과 비교한다.
- `server_runtime_only`는 재현성·응답성 참고자료일 뿐, 분석가 시간절감으로 해석하지 않는다.
- P01~P05가 모두 paired 되기 전에는 시간절감률을 발표 자료에 넣지 않는다.
- 공개 자료·합성 packet으로 얻은 결과는 실제 KIC 업무효과가 아니라 MVP 파일럿 결과로 표시한다.

## 계산식

- 시간 절감률 = `(수작업 평균 시간 - Agent 평균 시간) / 수작업 평균 시간`
- 재작업 감소율 = `(수작업 재작업 평균 - Agent 재작업 평균) / 수작업 재작업 평균`
- 중대 오류 탐지율 = `탐지한 중대 오류 수 / 전체 중대 오류 수`
- false-hold rate = `정상 packet 중 HOLD 수 / 전체 정상 packet 수`

## 결과 공개 원칙

1. 표본 수·입력 packet·실행일·모델·프롬프트·raw log를 함께 저장한다.
2. 평균뿐 아니라 중앙값과 범위를 표시한다.
3. 표본이 작으면 “파일럿 측정”이라고 표시하고 내부 전체 업무효과로 일반화하지 않는다.
4. 안전 게이트가 HOLD한 사례는 시간 절감보다 오류 회피·검토 품질 측면에서 해석한다.
5. 모델 장애·API 지연·부분 데이터 실패를 별도 케이스로 기록한다.
6. 원본 기록은 익명 operator ID와 run ID만 사용하고, 비공개 자료·실명·내부 투자판단은 공개 release에 넣지 않는다.

## 재현 명령

```powershell
# 실제 값으로 대체해서 같은 packet_id에 각각 기록
python .\measure_effect.py --condition manual --packet-id P01 --scenario clean --elapsed-minutes <분> --rework-count <회> --source-gaps <건> --calculation-inconsistencies <건> --decision REVIEW
python .\measure_effect.py --condition agent --packet-id P01 --scenario clean --timing-scope end_to_end_workflow --observed-minutes <분>

# 5개 packet이 모두 입력된 뒤에만 strict 검증
python .\validate_effect_measurement.py --strict
```

검증기는 값이 없을 때 `AWAITING_HUMAN_PAIRING`, 일부만 있을 때 `INCOMPLETE`를 반환한다. `READY_TO_REPORT`는 동일 범위의 5개 paired 기록이 존재한다는 뜻이지, 전체 업무에 대한 일반화나 수상 가능성을 보장한다는 뜻이 아니다.

## 본선 완료 기준

- 최소 5개 동일 packet 측정 완료
- 수작업·Agent 조건의 원본 stopwatch log 보관
- 오류 주입 결과와 정상 케이스 false-hold를 분리 보고
- 발표 PDF의 수치가 raw log와 일치
